Demonstrates the `lupi` compatibility system: "Balão Gatinho", a real Lupi
game (see `lupi-balao-gatinho/README.md`), running unmodified inside newbase
from source form — no Lupi devkit/compiler involved — and shown as an
ordinary sprite in the scene.

`scene.lua` calls `lupi_start("res/lupi_demo/lupi-balao-gatinho/lupi.yaml")`,
an RTTI-exposed function on the `lupi` system (see `src/lupi/lupi.cpp`), the
same mechanism used for e.g. `clock_update_add`. Switching to another demo
calls `lupi_stop()` automatically via `lupi::on_scene_change()`.

The game itself runs in its own, fully isolated `lua_State`; it can't see or
touch anything in this scene's Lua environment, and vice versa. Real carts
ship no compiled assets (no `sprites.lua`/`palette.lua`/compiled maps) — those
are normally generated by Lupi's own build pipeline. `lupi` reimplements that
step itself at boot time: `img/**.png` + `maps/**.png` are auto-discovered
and palettized into `Sprites`/`Palette`, `maps/*.json` (Tiled's export format)
is compiled into the same table shape the real pipeline produces, and
`require()` is replaced outright to serve all of this without touching disk
via Lua's own file I/O. See `doc/system_lupi.md` for the full picture.

Move with arrow keys / WASD, Z/X for action buttons.
